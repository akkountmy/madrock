# MADROCK COFFEE — сайт кофейни в Гомеле

Одностраничный сайт кофейни **MADROCK COFFEE**: витрина меню, предзаказ с самовывозом,
бонусная программа с отдельной страницей личного кабинета и акция недели с таймером.

Всё собирается в **один самодостаточный файл** `index.html` (стили и скрипты внутри),
фотографии лежат рядом в `assets/`. Ни фреймворков, ни CDN-скриптов — сайт открывается
и как обычный файл с диска, и с любого статического хостинга.

## Скорость загрузки

Сайт статический, без библиотек и сторонних домены — всё лежит рядом со страницей,
поэтому открывается быстро и на телефоне:

| Что | Как сделано |
|---|---|
| Фотографии | каждый кадр в четырёх файлах: 400 и 800 px по ширине в WebP и JPEG (у главного фото ещё 1280). Браузер сам выбирает вариант под экран (`<picture>` + `srcset`/`sizes`), класс `ph()` в `src/app.js` |
| Вес фото на телефоне | вариант 400 в WebP: ~11 КБ на кадр вместо прежних 153 КБ в JPEG |
| Загрузка фото | все, кроме главного, помечены `loading="lazy"` и грузятся по мере прокрутки; у каждой картинки указаны `width`/`height`, поэтому вёрстка не «прыгает» |
| Главное фото | прописано прямо в разметке (`src/body.html`) и помечено `fetchpriority="high"` — браузер находит его прелоадер-сканером, не дожидаясь скрипта |
| Шрифты | Manrope и Unbounded (11 файлов, ~285 КБ) раздаются с самого сайта, `font-display: swap`; сторонних доменов нет вообще |
| Стили и скрипт | встроены в `index.html` — лишних запросов нет; на GitHub Pages страница отдаётся сжатой |
| Обновление фото | `node tools/make-responsive.mjs` — пересобирает варианты из утверждённых кадров |

Проверка бюджета — `node tools/check-photos.mjs`: она печатает, сколько килобайт
скачает телефон и большой экран за полный обход страницы, и падает, если какой-то
файл или вся публикация выходят за установленный предел.

## Деплой на GitHub Pages

Репозиторий проекта: <https://github.com/akkountmy/madrock> (публичный, ветка по умолчанию `main`).
Сайт после публикации: <https://akkountmy.github.io/madrock/>.

Сайт публикуется автоматически: workflow `.github/workflows/pages.yml` собирает страницу
из `src/`, прогоняет проверки и выгружает **только** `index.html` и `assets/`
(служебные папки `research/`, `tools/`, `src/` на хостинг не попадают).

Пути к файлам относительные (`assets/…`), поэтому сайт работает и в подпапке
репозитория (`https://<логин>.github.io/<репозиторий>/`), и на своём домене.

### Что нужно заранее

- **Git for Windows** (`git --version` должен ответить версией). В комплект входит
  Git Credential Manager: при первом `push` он сам откроет окно входа на GitHub.
- Аккаунт GitHub. Локальный репозиторий уже подготовлен: `git init -b main` выполнен,
  файлы проекта лежат в индексе, служебное и черновое отсекает `.gitignore`
  (исходники фото, утверждённые кадры, черновые папки инструментов),
  а `.gitattributes` держит в репозитории переводы строк LF — так сборка на
  Linux-раннере и на Windows даёт одинаковый файл.

### Шаги

**1. Подпись автора коммитов** (один раз на компьютере):

```powershell
git config --global user.name "Имя Фамилия"
git config --global user.email "you@example.com"
```

Эти имя и адрес попадут в историю репозитория. Чтобы не публиковать личную почту,
включите на GitHub «Keep my email addresses private» и укажите адрес вида
`<ID>+<логин>@users.noreply.github.com` (ID виден в Settings → Emails).

**2. Первый коммит** (в папке проекта):

```powershell
cd <папка проекта>
git commit -m "Сайт MADROCK COFFEE: первая публикация"
```

Отменить или поправить подпись уже сделанного коммита: `git commit --amend --reset-author --no-edit`.

**3. Пустой репозиторий на GitHub**: github.com → **New repository**.

- имя репозитория даёт адрес сайта: `https://<логин>.github.io/<репозиторий>/`;
- **не** отмечать «Add a README file», «Add .gitignore», лицензию — они уже есть в проекте;
- видимость **Public** (Pages из приватного репозитория требует платного плана);
- **Create repository** → скопировать адрес `https://github.com/<логин>/<репозиторий>.git`.

**4. Связать и отправить**:

```powershell
git remote add origin https://github.com/<логин>/<репозиторий>.git
git push -u origin main
```

Если окно входа не появилось и просят логин/пароль: обычный пароль GitHub не подойдёт,
нужен токен — Settings → Developer settings → Personal access tokens → Tokens (classic) →
Generate new token (classic), права `repo` **и обязательно `workflow`**, иначе push файла
`.github/workflows/pages.yml` отклонят («refusing to allow a Personal Access Token to create
or update workflow»). Вместо токена можно взять SSH: `ssh-keygen -t ed25519 -C "you@example.com"`,
публичный ключ добавить в GitHub → Settings → SSH and GPG keys, затем
`git remote set-url origin git@github.com:<логин>/<репозиторий>.git`.

**5. Включить Pages**: Settings → Pages → Build and deployment → **Source: GitHub Actions**.
Без этого шаг `deploy` падает с `Get Pages site failed`.

**6. Дождаться публикации**: вкладка **Actions** → запуск «Сайт MADROCK → GitHub Pages».
Job `build` собирает страницу из `src/`, прогоняет три проверки и печатает
«файлов к публикации: N» (это `index.html` и `assets/`). Job `deploy` выдаёт адрес —
он же появляется в Settings → Pages: `https://<логин>.github.io/<репозиторий>/`.

**7. Проверить сайт** в браузере: каталог, предзаказ, личный кабинет. Хостинг статический —
ни Node, ни сервер после публикации не нужны.

### Обновление сайта потом

Правим `src/` и `assets/`, затем:

```powershell
node tools/build.mjs
git add .
git commit -m "Правки меню"
git push
```

Workflow пересоберёт и опубликует страницу сам. `index.html` руками не редактируем — это
результат сборки, его перезапишет `tools/build.mjs`.

Два практических замечания:

- **Имена файлов фото не меняются** (`hero-800.webp` и так далее), а Pages отдаёт статику
  с кешем около 10 минут: после замены кадра часть гостей ещё какое-то время увидит старую
  картинку. Если это мешает — дайте файлу новое имя (`hero-800-v2.webp`) и поправьте ссылку.
- Черновые папки инструментов (`.recenter-scratch/`, `_glam-tmp/`, `assets/_crops/`,
  `assets/_original/`) перечислены в `.gitignore`, поэтому `git add .` их не захватит.

### Свой домен

1. Файл `CNAME` в корне репозитория — одна строка с доменом (`madrock.by`). Workflow
   копирует его в публикацию, поэтому домен не слетает после каждой сборки.
2. DNS:
   - домен без `www` (apex): четыре A-записи — `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153` — и четыре AAAA: `2606:50c0:8000::153`,
     `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`;
   - поддомен (`www`, `coffee`): CNAME на `<логин>.github.io`.
3. Settings → Pages → Custom domain → тот же домен → **Save**, дождаться проверки DNS
   (обычно минуты, иногда до суток), затем включить **Enforce HTTPS**.
4. В `src/shell.html` прописать абсолютные `og:url` и `og:image` — для превью ссылок
   в мессенджерах нужны полные адреса.

Подробности — в документации GitHub:
[управление своим доменом для GitHub Pages](https://docs.github.com/ru/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

### Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `Please tell me who you are` | не настроена подпись автора — шаг 1 |
| `refusing to allow a Personal Access Token to create or update workflow` | у токена нет права `workflow` |
| `Updates were rejected… remote contains work` | репозиторий создан с авто-README. Надёжный путь: `git fetch origin`, `git reset --soft origin/main`, `git commit -m "…"`, `git push -u origin main` — наш README заменит авто-README, история останется линейной. Если авто-README не нужен, можно один раз `git push -u origin main --force` |
| job `deploy`: `Get Pages site failed` | не включён Pages — шаг 5 |
| job `deploy`: `Resource not accessible by integration` | Settings → Actions → General → Workflow permissions → **Read and write permissions** |
| сайт отдаёт 404 | подождать 1–2 минуты после зелёного workflow; проверить, что репозиторий публичный и Source = GitHub Actions |
| страница открылась без картинок | в `index.html` попали абсолютные пути; их ловит шаг-страж workflow, локально — `node tools/render-check.mjs` |
| упали проверки в CI | те же команды локально: `node tools/build.mjs`, `node tools/render-check.mjs`, `node tools/check-photo-refs.mjs`, `node tools/check-photos.mjs` |

Публикация Pages из **приватного** репозитория требует платного плана GitHub —
репозиторий должен быть публичным либо нужен Pro/Team.

## Разделы сайта

1. **Шапка** — пять пунктов меню, статус «Открыто · пять кофеен до 23:00» по реальному
   времени, иконки кабинета и предзаказа, кнопка меню на телефоне.
2. **Полоса надписей** под шапкой — факты о кофейне, ключевые цифры выделены красным.
3. **Титульный блок** — фотография во всю ширину контента, текст поверх снимка.
4. **Акция недели** — предложение меняется по номеру ISO-недели, таймер до воскресенья 23:59.
5. **Хиты бара** — шесть позиций.
6. **О нас** — шесть преимуществ.
7. **MADROCK Club** — бонусы, три уровня (Rock 5% / Hard Rock 7% / Mad Rock 10%),
   карта «10-й напиток в подарок»; блок «Уровни» тянется до низа столбца с карточками.
8. **Меню** — 35 позиций в 6 категориях, поиск, фильтры, карточка напитка с настройкой.
9. **Предзаказ** — четыре шага, четыре способа связи, выбор кофейни и времени.
10. **Вход и регистрация** — карточка с формой; после входа открывается **отдельная
    страница кабинета** (`#account`) с бонусами, QR, печатями, купонами и историей заказов.
11. **Отзывы, лента Instagram, контакты пяти кофеен, подвал.**

## Как это работает

- **Акция недели.** `app.js` считает ISO-неделю и берёт `PROMOS[номер % 8]`. Скидка
  применяется автоматически: в итогах появляется строка «🔥 Акция недели».
- **Бонусы.** Кэшбэк 5 → 7 → 10% по сумме заработанных бонусов (0 / 500 / 1500),
  списание до 50% чека, каждый 10-й напиток — купон, при регистрации 50 бонусов и печать.
- **Состояние** хранится в `localStorage` (`madrock.cart.v1`, `madrock.user.v2`,
  `madrock.fav.v1`). Демо-вход: любой телефон и пароль от 4 символов.
- **Поиск по меню** синхронизирован с фильтром: браузерное автозаполнение поля
  не может «отфильтровать» каталог в пустоту, а пустой список объясняет причину
  и предлагает сбросить поиск.

## Проверки качества

Аудит запускается в браузере: `tools/site-audit.js` (ширины, блоки, каталог, кабинет,
поиск, телефонные версии 430/414/390/360 px) и `tools/button-audit.js` (нажатие по каждой
кнопке, корзина, оформление заказа, карточка товара). Оба подключаются к странице
при открытии с параметром `audit=`.
